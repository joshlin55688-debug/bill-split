## 1. 設計理念與取捨

- **「看盤軟體」而非「遊戲畫面」**：深色模式、等寬字、終端機日誌、折線/K 線圖。刻意冷硬、數據感，符合企劃定位。
- **核心是公式，不是動畫**：所有戰鬥用企劃提供的數學式即時運算，因此能「一秒算完數小時掛機」（離線回測的關鍵）。
- **圖表全用 Canvas 手刻**：為了維持單檔零依賴，沒用 Chart.js。折線圖、K 線圖都是 `<canvas>` + 約 20 行繪製碼。
- **取捨**：節點串接式視覺化編輯器、線上排行榜這兩個重型/需後端的功能，v1 先做「精簡替代版」，完整版列入 TODO。

## 2. 架構筆記

### 2.1 全域狀態 `S`
```
S = {
  gold, stone(洗鍊石), block(重鑄方塊), scroll(賦予捲軸),
  depth, maxDepth, hpPct, running,
  tactic, customHp, agg, farm,          // 戰術設定
  roster:[冒險者], party:[上陣id], nextId,
  inv:[裝備], tavern:[待雇用],
  log:[], bossLog:[],
  goldHist:[折線取樣], hpCandles:[K線], goldRateAcc/Timer,
  week, bossBest, lb:[排行榜], bossDeadline,
  stats:{kills,goldTotal,drops,retreats}, lastTs
}
```
> 同樣有 `load()` migration（用 `fresh()` 補欄位），加新欄位記得補進 `fresh()`。

### 2.2 核心公式（完全照企劃，集中在這些函式）
| 函式 | 公式 |
|---|---|
| `teamPower()` | HP×0.2 + ATK×2.0 + DEF×1.5 |
| `combatStep()` 勝率 | TeamPower /(TeamPower+EnemyPower)，再加破甲(pierce) |
| HP 消耗 | min(100, EnemyPower/TeamPower ×15%)，再被吸血(lifesteal)降低 |
| 金幣 | EnemyPower ×0.5，再被貪婪(greed)加成 |
| 掉落率 | BaseDrop ×(1+LUK/100) ×(1+機運fortune) ×環境乘區 |
| `enemyPower(depth)` | 38×1.155^depth + depth×9 + 30（指數成長） |

### 2.3 一個 `combatStep()` 兩用
同一個戰鬥函式被「即時戰鬥（含 log/繪圖）」與「離線批次回測（silent，跑上萬次）」共用，確保線上線下結果一致。這是放置遊戲很重要的設計：**模擬邏輯只能有一份**。

### 2.4 主迴圈
- `setInterval(gameTick,200)`：每 200ms 跑一次；其中戰鬥節奏為每 1200ms 一場、金幣速率每 5s 取樣一次。
- **戰鬥閘門在 `gameTick` 的 `if(S.running && ...)`**，不是在 `doLiveFight` 內 → 見第 4 節的測試教訓。

## 4. 踩過的坑與教訓

### ⚠️ 教訓 1：戰鬥閘門的位置
- 測試時用 `for` 迴圈連續呼叫 `doLiveFight()` 12 次，結果 HP 一路被打到 0%、撤退後又繼續打。
- **原因**：`doLiveFight()` 內部**沒有**檢查 `S.running`；真正的閘門在 `gameTick` 的 `if(S.running)`。我繞過了 gameTick 直接硬呼叫，所以撤退後仍繼續。
- **結論**：這是測試方式的問題，遊戲本身正確。但記下來：**狀態閘門放在排程層（tick）還是動作層（fight），測試與重構時要清楚**，否則容易誤判成 bug。

### ⚠️ 教訓 2：重繪會清掉動態產生的 log 區塊
- `autoReroll` 把過程寫進 `#arLog`，但 `renderGear()` 重繪 forge 面板時會把它清掉。
- **處置**：洗鍊結束後重繪，再「reattach」把 log 重新塞回 `#arLog`。屬可接受的小 workaround。
- **更好的做法（未來）**：把洗鍊 log 存進 `S`，由 render 統一輸出，而非塞進會被重建的 DOM。

### ⚠️ 注意：currency 列更新時機
- `renderGear()` 不會刷新頂部金幣/石頭數字；靠 `updateTop()` / `refreshDash()` / `gameTick` 更新。測試直接改 `S.stone` 後頂列會短暫顯示舊值，按鈕實際操作則正常。

### ✅ Canvas 圖表的小細節
- 每次繪製都 `cv.width=cv.clientWidth` 重設，避免 retina/縮放糊掉。
- K 線：開=戰前HP、收=戰後HP，漲（回血）綠、跌（扣血）紅——雖然這遊戲 HP 多半在跌，視覺上仍清楚。
